# Isolated V8 poison acceptance

Run `poison_acceptance.py tx-failure --run-id UNIQUE --exclusive-pbs-kafka-slot` and `pending-ack` only after runtime explicitly grants the shared PBS/Kafka fault slot. These are actual service/Kafka/PG acceptance tests, not unit tests. They reuse the isolated fixture token and seed without logging token headers. Production v3 remains unchanged.

`tx-failure` makes the first DLQ transaction fail using a test-only conditional PG trigger. Its second attempt waits on an advisory lock; durable attempts must equal five, state remains counting, and no matching real DLQ event exists. An actual PBS crash precedes recovery. The budget stays five and the DLQ has exactly one logical ID. A subsequent healthy message in the same single partition must create one Build and a real DVS product matching source rows.

`pending-ack` blocks the DLQ state update, then pauses the exact Kafka CRI process from its kind ancestor (asserting `/proc` State T). Before releasing the SQL barrier, it installs one run-commented INPUT DROP inside the Kafka Pod's separate network namespace, limited to the old PBS source IP, Kafka destination IP and TCP9092. This prevents a queued CommitRequest from being processed after broker resume. It confirms the DLQ committed while broker ACK is impossible, force-crashes PBS, confirms the old CRI task died, then resumes Kafka. Before replacement PBS starts, consumer committedOffset must still point at the poison message. The old-IP rule remains while a different-IP replacement re-reads and ACKs, then the healthy product completes. Finally removes the exact rule and all test SQL fixtures and restores service health. It never deletes/scales Kafka, whose fixture storage is ephemeral.

Evidence under the run-specific prefix includes poison rows before/after, five-attempt state, deterministic DLQ ID, raw Kafka DLQ messages/headers and CLI exit codes, consumer/end offsets, exact Pod/CRI identity, STOP/CONT status, scoped rule hit counters/cleanup, actual PBS crash, healthy dispatch and HTTP product responses. A second ordinary restart checks stable attempts/unique DLQ, in addition to the independently proven unconfirmed-ACK window.

This kernel lacks `CONFIG_INET_DIAG_DESTROY`; `ss -K` cannot reliably destroy queued sockets. A broker pause alone also fails this proof: its receive buffer can contain an offset commit that succeeds after CONT. The harness uses and verifies the narrowly scoped rule rather than resetting consumer offsets or treating an ordinary restart as ACK-failure evidence. Failed exploratory runs remain in the evidence directory.

Before replacement PBS starts, committedOffset 114 versus endOffset 115 proves the poison offset remains unread/ACK-uncommitted. The old-flow DROP recorded 4 packets/728 bytes, stayed installed while the different-IP replacement recovered and produced the healthy output, then was removed.
- `poison-final-cleanup.json`: independent final verification exit 0; Kafka same Pod UID `6b54b67a-02a6-4f7b-8a40-22627a59faed`, restartCount 0, process not stopped, INPUT only ACCEPT policy, test SQL trigger/function/sequence/holder counts all zero; all actual exploratory exit codes retained.

The initial transaction-failure harness run failed only because its formatter parser chose the headers JSON instead of the final-tab payload. Pending-ACK r1 correctly rejected a buffered offset commit that completed after broker resume; r2–r4 rejected unsupported/malformed socket-destroy attempts rather than declaring recovery proven. Those failed raw runs were not overwritten. r5 passed the basic flow-drop proof, and r6 additionally retained the old-IP rule through successful recovery as required.
