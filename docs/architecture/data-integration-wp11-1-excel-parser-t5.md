## 两种交付顺序

两种方案都先完成 WP11.2 的最小真实链路。WP11.6 的基础拒绝行为应从第一批出现，完整容量矩阵随对应格式、sheet 和发布能力完成后封存。

| 选择 | 建议顺序 | 第一项可验收增量 | 适用条件 |
| --- | --- | --- | --- |
| A · 先覆盖多 sheet 业务 | WP11.2 → WP11.4 → WP11.3 → WP11.5 → WP11.6 全量容量验收 | 一个工作簿提取多个表，业务输出与错误数据集一起发布，失败时保持旧结果 | 首批客户主要上传 XLSX，且需要区分有效数据和错误行。WP11.4 启动前需明确 S5 的合并及组清单策略 |
| B · 先覆盖输入格式 | WP11.2 → WP11.3 → WP11.4 → WP11.5 → WP11.6 全量容量验收 | 单表管道逐个接收真实 XLS、XLT、XLTM、XLTX、XLSX、XLSM 样本 | 首批客户存在必须读取的旧格式，或组清单策略短期内仍待定 |

若首批样本以 XLSX 为主，建议选 A。它能更早用真实工作簿验证错误隔离和多输出，再把同一套验收扩到其余格式。如果产品提供必须上线的 XLS/XLT 样本，选 B。现有估算沿用 T0，WP11.1–WP11.6 合计 28–54 工程人日，顺序变动不改变估算口径，也不给出客户交付日期。

## 分批能力和验收

| 工作包 | 本批交付 | 真实后端验收 | T0 工程人日 |
| --- | --- | --- | ---: |
| WP11.2 | 单 XLSX、单个 worksheet，固定输入快照、明确的表头/范围、解析后发布单产物 | 从已提交的原始 XLSX 文件发起构建。源 head 改变后重跑仍读固定版本；核对前导零、长数字字符串、日期和空值；损坏/超限输入保持旧 head | 6–10 |
| WP11.3 | 补齐 XLS、XLT、XLTM、XLTX、XLSM，保留 XLSX 回归 | 六种格式各用真实样本核对结构和值；XLSB 和伪装扩展名有明确错误。含宏工作簿仅读取数据，公式、缓存值及受保护文件策略由产品确认 | 6–14 |
| WP11.4 | 多 sheet、多业务输出和 errorDataframe | 有效行和错误行分流。错误项可定位输入版本、文件、sheet、物理行、字段及稳定错误码。第二个输出发布失败时全部旧版本仍可读；提交后丢响应及进程重启可恢复同一组回执和清单 | 6–12 |
| WP11.5 | 非表格区域抽取、跨文件 schema | 用指定区域的样本核对抽取边界；源文件顺序改变后，列名、缺列、同名冲突和类型合并结果可复核 | 6–12 |
| WP11.6 | 大文件、损坏文件和容量验收 | 校验工作簿字节、解压后体积、sheet、行/列数等限额；记录耗时、DVS/PBS 峰值 RSS、输出大小及错误行计数。超限时保持旧版本、无新回执或可见半成品 | 2–3 |

## 请产品拍板

1. **顺序与样本。** 选择 A 或 B，提供首批优先格式、匿名真实样本、sheet/行/列规模、典型坏数据和预期延迟。
2. **错误隔离。** 明确哪些是可输出至 errorDataframe 的行错误，哪些应让整次构建失败。确定错误数据集是否总是发布、空错误数据集的语义，以及是否保存原始单元格值。
3. **工作簿语义。** 明确首批表头/范围、隐藏表、公式缓存、日期系统、受保护文件和跨文件 schema 冲突的处理办法。确认含宏格式只提取数据。
4. **开工和验收。** 确认所选顺序及首批标准后，启动 WP11.2。WP11.4 在发布协议、S5 签署和清单关联明确后再进入实现。WP11.6 以样本实测确定容量口径。

本文件交付的是裁决选项。产品确认结果应另行记录，以便把选定顺序和验收事项同步到排期与矩阵。
